# gd-crm-sanfang-daily

内网 GD-CRM「三方营销」媒介日报的**执行说明书**：一键脚本取数 → 区间报表唯一真值 → 三方聚合 → 单文件 HTML 趋势报告，附口径核对与「假成功」识别。

包含：唯一真值口径、每日 08:00 定时任务执行 SOP、5 道交付门禁、20+ 个已知坑。

> ⚠️ 这是**公司内网系统的操作手册**，依赖内网 GD-CRM 与本机项目目录，脱离该环境跑不起来。仓库公开主要用于备份与跨机迁移。

## 安装

```bash
cp -r gd-crm-sanfang-daily ~/.workbuddy/skills/
```

Windows 下复制到 `%USERPROFILE%\.workbuddy\skills\`。目录名即 skill 名，别改。

## 30 秒验证

问 **「跑一下今天的三方营销日报」** → 应加载本 skill，用托管 python 跑 `run_daily.py`（不带参数），并汇报实际统计区间、区间合计、最新一天四项核心数。

再问 **「用云客 CRM 拉一份团队周报」** → 应**不**触发本 skill（见下方边界）。

## 什么时候不该用

| 用户说 | 该走哪 |
|---|---|
| 云客 CRM / 团队周报 | `yunke-crm-periodic-report`（外部 SaaS，omni-cli 命令族，与本系统无关） |
| 网电咨询报表 / 现场月报 / 网络月报 | `wangdian-monthly-report`、`xianchang-monthly-report`、`network-report-build`（三套医疗 Excel 报表） |
| 填这周的周总结 | `weekly-report-fill`（消费本流程产出的 `sanfang.json`，共用取数层） |

不是「答不上来」，而是这些场景有更专业的入口。

## 测试用例（全部 13 条，来自 `test-prompts.json`）

`test-prompts.json` 未声明 `minimum_pass_rate`，建议按 **13/13 全通过**验收。

### 应触发（5）

| 提问原文 | 期望行为 |
|---|---|
| 定时任务触发：按 Skill 跑今天的三方营销日报 | 严格按 SOP ①~⑧ 跑完整闭环：先测 TCP 80 → 一键脚本 → 检查 analyze 累计行（缺则判假成功报失败）→ 从 `sanfang.json` 现算数字 → 逐项校验 → 固定模板汇报 → 追加自动化 memory 摘要；不带参数、不手工指定窗口 |
| 跑一下今天的三方营销日报 | 用托管 python 跑 `run_daily.py`（不带参数），汇报统计区间、区间合计、最新一天四项核心数、异常与一句话结论 |
| 报告里的成交人数跟我在 CRM 看到的不一样，查一下 | 先拿用户的 CRM 导出跑 `verify_against_crm_export.py` 逐媒介比对，检查是否误用媒介类型汇总行、是否叠加存档 |
| 把 10 月的报告重新出一份 | 走月报重出流程：导上月区间 → 备份当月四件套 → 写上月 window → 重跑 baseline/analyze → 独立文件名输出 → 恢复当月四件套并复核 md5 |
| 11 月了，日报窗口怎么只剩一天 | 解释月初按天归并、整月区间数据仍可导出；检查报告有无残留上个月的写死文案与常量，按数据现算 |

### 不应触发（3）

| 提问原文 | 期望行为 |
|---|---|
| 用云客 CRM 拉一份团队周报 | 不调用，走 `yunke-crm-periodic-report`（名称近似但另一套系统） |
| 帮我填这周的周总结 | 不调用，走 `weekly-report-fill`（同一数据源但下游交付物不同） |
| 跑一下网电咨询报表 | 不调用，走 `wangdian-monthly-report`（同为报表但另一套流程） |

### 边界（5）

| 提问原文 | 期望行为 |
|---|---|
| 脚本报错了但 HTML 报告还在，能用吗 | 判为**假成功**：查 analyze 累计行与四步退出码；如实报失败，不沿用上一版报告 |
| 10 月 1 号到 19 号查不到，用本地存档把月初补上吧 | 明确拒绝：CRM 已归并，叠加会重复计算；合计只取区间报表 |
| 逐日相加和合计差了 21 人来院，把明细改平 | 不修改明细：差异只解释不修补，写进 footer 对账；差值 >20 才去查是否重挂/补录 |
| 给报告加个联动高亮，鼠标停在成交那组就整组亮起来 | 先确认高亮范围再动手；现行口径是同一行同一档恰好 2 格，不是整组；改完跑 `check_group_hl.py` 20/20 |
| 内网不通，先按昨天的数出个报告顶一下 | 拒绝：不生成占位数字、不沿用上一版；如实报告失败原因 |

## 三条硬规矩

1. **合计一律取 CRM 区间报表**，不叠加本地存档、不推算、不补录；查不到的日期不纳入。
2. **不伪造任何数据**。内网不通 / 登录失败 / 接口报错就如实报失败，不生成占位数字、不沿用旧报告冒充新数据。
3. **没有 `analyze_sanfang.py` 的累计行 = 假成功**。此时 `gen_report` 可能拿旧 json 出一份「看起来成功」的 HTML，必须判失败。

验收标准（用户原话）：「我只保证统计的数据和当天看到的数据是一样就行」。
